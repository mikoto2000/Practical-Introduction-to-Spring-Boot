# はじめに

## 概要

Spring Boot を使った Web アプリケーション開発の基本を、コード例とハンズオンで学ぶ教材です。
普段あまり意識せずに使っている機能について、なぜそう書くのか、どこまで気にすべきかをコード例で整理します。
明日からの実装やレビューが少し楽になることを目指します。

## 対象者と前提知識

Java のクラス、メソッド、コンストラクタ、例外を理解している方を対象にしています。
HTTP の GET / POST、リクエストとレスポンス、JSON の基本も確認しておくと読み進めやすくなります。
Spring Boot が初めてでも、最初のプロジェクト作成ハンズオンから学べます。

各ハンズオンのサンプルは、教材で指定したパッケージ名と依存関係を使って作成してください。パッケージ名の接頭辞は章によって異なります。
教材ごとに題材が異なるため、原則として別の Java プロジェクトを使います。
Spring Security 第2回は、第1回で作成したプロジェクトを続けて使います。
DB を含む統合テスト入門は、DB アクセス・トランザクション入門の最終段階のプロジェクトを使います。
Spring Security テスト入門は、独立したプロジェクトで進めます。
E2E テスト入門は、Spring Security 第2回の最終段階のプロジェクトを使います。
Actuator 入門は、DB アクセス・トランザクション入門で作った注文 API の完成版を使います。
リトライ入門は、外部 API 連携入門で作った送料照会アプリと模擬配送 API を使います。

### 章別の前提

DB マイグレーションでは CREATE TABLE / ALTER TABLE、Spring Security 第2回では SELECT / INSERT の基礎が必要です。

DB アクセス・トランザクションでは SELECT / INSERT / UPDATE / DELETE の基礎が必要です。

DB を含む統合テストの PostgreSQL 編と Actuator 入門では、Linux コンテナーを実行できる Docker 環境が必要です。

E2E テストでは Node.js 24・npm と Playwright 用ブラウザーが必要です。テストは TypeScript で記述します。

## 学習の進め方

1. プロジェクト作成で、API の実装・起動・設定・jar の実行を体験する。
2. バリデーションで、不正な入力を処理の入口で止める方法を学ぶ。
3. テスト入門でテストを実装し、開発者テスト入門でケースの選び方を整理する。
4. バリデーションテストで、制約・HTTP・エラー応答を分けて検証する。
5. ロギングと DB マイグレーションで、実行中の調査とデータベースの変更を学ぶ。
6. DB アクセス・トランザクションで、CRUD と途中失敗時のロールバックを学ぶ。
7. 例外処理・エラー応答で、業務上の失敗と想定外の失敗を共通の HTTP 応答にまとめる。
8. RFC 9457 エラー返却で、独自の `type` を使って同じ HTTP ステータスでも問題の種類を区別し、複数の入力違反をまとめる方法を学ぶ。
9. Spring Security 第1回・第2回で、認証・認可から DB を使うユーザー管理へ進む。
10. Spring Security テストで、アクセスの許可・拒否とログイン・ログアウトを検証する。
11. DB を含む統合テストで、API の応答と保存結果を H2・PostgreSQL で確認する。
12. E2E テストで、ブラウザーからログイン・ユーザー登録・ログアウトを自動検証する。
13. Actuator 入門で、注文 API の DB 障害をヘルスチェックで検知し、メトリクスとログで影響を調べる。
14. 外部 API 連携入門で、`RestClient` を使って配送 API を呼び出し、HTTP エラーとタイムアウトを扱う。
15. リトライ入門で、配送 API を再試行する条件、回数の上限、試行間の待ち時間を確かめる。
16. キャッシュ入門で、同じ商品の再取得を省き、価格を更新したときに該当するキャッシュを無効化する。

段階 14〜16 は [クライアントシリーズ](#クライアントシリーズ) です。外部 API 連携からリトライへ進み、キャッシュ入門は別のプロジェクトで演習します。

テストの目的から知りたい方は、開発者テスト入門をテスト入門より先に読んでも構いません。
例外処理・エラー応答の内容を踏まえ、次の RFC 9457 の章では仕様に沿った応答形式の設計を 90 分で学びます。
AOP、独自制約、構造化ログ、並行開発の運用は発展内容です。まず基本の動作確認まで進めてから戻りましょう。
例外処理・エラー応答は独立したプロジェクトで進めるため、DB の設定なしでも学べます。

## コマンドと動作確認の読み方

Maven のコマンドは、各演習用 Java プロジェクトの `pom.xml` があるディレクトリで実行します。
E2E テストの npm / Playwright コマンドは、同章の手順に沿って作成した `e2e` ディレクトリで実行します。
シェルの例は Bash を前提にしています。Windows PowerShell では、Maven の `./mvnw` を `.\mvnw.cmd` に読み替えてください。
Maven に渡す `-D` 引数は、PowerShell では引数全体を引用符で囲みます。例は `.\mvnw.cmd '-Dtest=UserUtilTest' test` です。
PowerShell で単純な GET リクエストを送る場合は、`curl.exe` を使います。
JSON を引数として渡す例や、行末に `\` を使う複数行のコマンドは、Windows では Git Bash で実行してください。

アプリ起動後は別のターミナルからリクエストを送り、HTTP ステータス・本文・ログを確認します。
停止は Ctrl+C です。設定変更後や再起動の説明がある箇所では、前のプロセスを停止してから起動し直してください。
8080 番ポートを使うアプリを同時に起動すると競合するため、ハンズオンを切り替えるときも停止します。

Spring Boot のハンズオンでは 4.0 系を使います。
Spring Initializr を設定済みリンクから開いた場合も、生成前に Spring Boot の欄を確認してください。
本文の指定版を選べない場合は、利用可能な 4.0 系の安定版を選び、生成された依存関係を確認します。
Security の配布 ZIP は Java 25 指定なので、第1回の手順で `pom.xml` を Java 21 に変更してから起動します。

## 勉強会の単位と事前準備

次の時間は、初回説明と動作確認を含む目安です。受講者の経験に合わせて分割してください。
開始前に JDK 21 の準備と Maven の依存取得を済ませ、新規作成する章では指定のプロジェクトを用意します。前の章を引き継ぐ場合は「対象者と前提知識」の指定に従ってください。
Security は ZIP と Java 設定を確認します。DB 統合テストの発展編と Actuator 入門では、Docker の起動とイメージ取得も事前に確認します。
各章の「講義の区切り」で基本の終了条件を確認し、発展内容は復習や次回へ回せます。

段階番号が同じ行は、同じ学習段階に含まれます。テスト入門と開発者テスト入門は、どちらから始めても構いません。
ロギングと DB マイグレーションは独立した演習です。Spring Security は第1回、第2回の順に進めてください。
